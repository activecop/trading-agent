Clonar o Projeto

Vamos obter o código-fonte do repositório e preparar o ambiente de trabalho local.

terminal 
# 1. Clonar o repositório
git clone https://github.com/luis-garces/trading-agent.git
cd trading-agent

# 2. Criar cópia do ficheiro de variáveis de ambiente
cp .env.example .env

# 3. (Opcional) Executar o script automático de estrutura
# Linux/macOS:
chmod +x criar_estrutura.sh && ./criar_estrutura.sh
# Windows PowerShell:
.\criar_estrutura.ps1
Atenção: O ficheiro .env contém as tuas chaves secretas. Nunca o partilhes ou faças commit para o Git. Já está incluído no .gitignore.

Gerar Chaves de Segurança

O agente cifra as chaves API em repouso usando o algoritmo Fernet. Precisas de gerar uma chave mestra única para o teu ambiente.

Gerar a Chave Fernet

terminal 
# Instalar a biblioteca cryptography (uma vez só)
pip install cryptography

# Gerar a chave
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

Copia o resultado (algo como gAAAAABm...) e cola-o no ficheiro .env:

.env 
FERNET_KEY=a_tua_chave_gerada_aqui
TRADING_MODE=PAPER
MAX_DAILY_DRAWDOWN_PCT=15.0
MAX_POSITION_SIZE_PCT=2.0
Boa prática: Guarda uma cópia da FERNET_KEY num gestor de palavras-passe. Se a perderes, não conseguirás descifrar as chaves API já guardadas.

Configurar as Exchanges

Vamos criar as chaves API na Binance e na Coinbase com as permissões mínimas necessárias.

🟡 Binance

  1. Acede a Binance.com → API Management
  2. Clica em "Create API" e escolhe "System generated"
  3. Em permissões, ativa APENAS:
    • ✅ Enable Reading
    • ✅ Enable Spot & Margin Trading
    • ❌ NUNCA ativar "Enable Withdrawals"
  4. Em "IP Access Restrictions", escolhe "Restrict access to trusted IPs only" e insere o IP da tua máquina
  5. Copia a API Key e a Secret Key (a secret só aparece uma vez!)

🔵 Coinbase Advanced

  1. Acede a portal.coinbase.com → API
  2. Clica em "Create API Key"
  3. Nome: trading-agent
  4. Permissões: View + Trade (nunca Transfer)
  5. Copia a API Key, API Secret e Passphrase

Adicionar ao .env

.env 
# Binance
BINANCE_API_KEY=a_tua_binance_api_key
BINANCE_API_SECRET=a_tua_binance_secret

# Coinbase Advanced
COINBASE_API_KEY=a_tua_coinbase_key
COINBASE_API_SECRET=a_tua_coinbase_secret
COINBASE_PASSPHRASE=a_tua_passphrase
Segurança obrigatória: Ativa 2FA em ambas as contas. Usa IP whitelist. Nunca partilhes as tuas chaves, nem com suporte técnico.

Iniciar a Aplicação com Docker

O docker-compose.yml orquestra três serviços: base de dados PostgreSQL, cache Redis e o backend FastAPI.

terminal 
# Construir e iniciar todos os serviços
docker-compose up --build

# Para correr em background (daemon):
docker-compose up -d --build

# Ver logs em tempo real:
docker-compose logs -f backend

Iniciar o Frontend (novo terminal)

npm install

Acede a http://localhost:3000 para ver o dashboard.

Explorar o Dashboard Web

O dashboard é a tua interface principal. Apresenta-se em modo escuro por defeito, com toggle para claro no canto superior direito.

Secções Principais

  • 📊 Visão Geral: PnL total, capital atual, drawdown diário, número de trades ativos
  • 📈 Gráficos em Tempo Real: Preços, order book, indicadores técnicos (EMA, RSI, MACD)
  • 🎯 Sinais Ativos: Lista de sinais BUY/SELL/HOLD gerados pelas estratégias
  • 💼 Posições Abertas: Trades em curso com stop-loss e take-profit visíveis
  • 📜 Histórico: Todos os trades executados, com explicação do motivo
  • 🛑 Kill Switch: Botão de emergência para parar tudo imediatamente
Tema: A tua preferência é guardada no localStorage e respeita o prefers-color-scheme do sistema como fallback.

Configurar Estratégias de Trading

O agente inclui três estratégias modulares. Podes ativá-las individualmente e ajustar os seus parâmetros no dashboard.

1. Mean Reversion (RSI + Bollinger)

Ideal para mercados laterais. Compra quando o preço toca na banda inferior de Bollinger e o RSI está abaixo de 30.

ParâmetroValor PadrãoDescrição
RSI Period14Período do RSI
RSI Oversold30Limiar de sobre-venda
Bollinger Period20Período das bandas

2. Momentum (EMA Cross + Volume)

Segue tendências fortes. Compra quando a EMA rápida cruza acima da EMA lenta e o volume é superior à média.

3. Arbitragem Inter-Exchange

Aproveita diferenças de preço entre Binance e Coinbase. Executa compra numa exchange e venda simultânea na outra.

Risco financeiro: Nenhuma estratégia garante lucro. Testa sempre em Paper Trading durante pelo menos 30 dias antes de considerar o modo Live.
8

Gestão de Risco

O módulo de risco é obrigatório e não pode ser desativado. Protege o teu capital com múltiplas camadas de segurança.

Camadas de Proteção

  1. Position Sizing: Cada trade arrisca no máximo MAX_POSITION_SIZE_PCT (padrão: 2%) do capital
  2. Stop-Loss Automático: Cada ordem tem SL calculado com base no ATR
  3. Take-Profit Automático: Alvo definido pelo ratio risco/recompensa (mínimo 1:2)
  4. Drawdown Diário: Se o capital cair MAX_DAILY_DRAWDOWN_PCT (padrão: 15%), o agente para automaticamente
  5. Kill Switch Manual: Botão de emergência no dashboard cancela todas as ordens abertas

Configurar Limites

.env 
# Risco máximo por trade (1-2% recomendado)
MAX_POSITION_SIZE_PCT=2.0

# Drawdown diário máximo antes de pausa automática
MAX_DAILY_DRAWDOWN_PCT=15.0

Ativar o Modo Live (com Cuidado)

A transição de Paper para Live Trading é deliberadamente difícil. O agente só permite ativar o modo Live se cumprires todos estes critérios:

Checklist Obrigatória

  • ✅ Mínimo 30 dias de Paper Trading contínuo
  • ✅ Paper Trading com lucro positivo nesse período
  • ✅ Backtest com Sharpe Ratio > 1.0
  • ✅ Backtest com Max Drawdown < 15%
  • ✅ Confirmação manual explícita do utilizador (duplo clique + código de verificação)

Ativar o Modo Live

.env 
# Mudar de PAPER para LIVE (só após validação completa)
TRADING_MODE=LIVE

Depois de alterar, reinicia o Docker:

terminal 
docker-compose restart backend
AVISO LEGAL: Trading algorítmico envolve risco de perda total do capital. Começa sempre com montantes muito pequenos. Este sistema não constitui aconselhamento financeiro.

Troubleshooting e FAQ

❌ "Erro de autenticação na Binance"

Causa: Chaves API incorretas ou relógio do sistema dessincronizado.

Solução: Verifica as chaves no .env e sincroniza o relógio do sistema (a Binance rejeita pedidos com timestamp desviado > 1s).

❌ "Porta 5432 já em uso"

Causa: Já tens um PostgreSQL local a correr.

Solução: Altera a porta no docker-compose.yml para 5433:5432.

❌ "Rate limit exceeded"

Causa: Excedeste o limite de pedidos da exchange.

Solução: O agente já tem retry com backoff exponencial. Se persistir, reduz a frequência de atualização no dashboard.

❌ "Tema não muda"

Causa: Cache do browser.

Solução: Limpa o localStorage (DevTools → Application → Local Storage → Clear) e recarrega.
